# 0001 勾选名单决定中转节点

## 背景

两个平台曾根据不同的规则保留节点，同名节点也可能让测速使用另一份订阅的配置。

## 决策

移除屏蔽名单，直接丢弃旧屏蔽数据，无需迁移、备份或提示。每个已勾选的名称只有一个节点归属。整理时以勾选名单和最新订阅的交集为准，实时中转入口组用于检测外部变化。首次初始化和升级时重新下载全部订阅。首次缺少勾选名单时，按订阅和节点的展示顺序，从实时组中为每个名字选定第一个匹配项。任一订阅下载失败时保留原配置和勾选名单，下次启动或手动刷新再试。没有匹配节点时请到「管理节点」勾选。两个实现通过同一套 JSON 用例验证整理计划。

## 影响

当前入口必须在整理后的名单中。若被取消或已失效，按配置的指标从最近一轮测速成功的节点中选最快项，缺少结果时按管理节点顺序取首项。新一轮测速开始时清除供整理使用的旧结果。旧版测速记录只有在名称归属无歧义时才用于排序。

先校验并重载配置，收到传输错误时保留已经写入的文件和勾选名单，并在约 10 秒内读取状态确认。仅在发送前写入失败或重载请求收到带响应体的 HTTP 错误时回退。重载未确认时暂停入口切换，直到刷新状态确认配置生效。切换时核对实时入口、节点归属和固定出口链路，失败且链路仍符合预期时再试一次，成功后短暂等待并再次核对。初始化只有在计划指定的入口得到确认后才完成，切换失败后下次启动或刷新会按最新有效测速结果重新选择。若名单为空，整次更新取消。

保留订阅和节点的原有顺序，并保留其他策略组还在引用的订阅的代理提供者定义。使用链路盒子管理的订阅源的其他策略组也只会看到已勾选的节点，需要全部节点的策略组请使用 Clash Verge 自己的订阅源。
