# 0001 勾选名单决定中转节点

## 背景

两个平台曾根据不同的规则保留节点，同名节点也可能让测速使用另一份订阅的配置。

## 决策

移除屏蔽名单，直接丢弃旧屏蔽数据，无需迁移、备份或提示。每个已勾选的名称只有一个节点归属。整理时以勾选名单和最新订阅的交集为准，实时中转入口组用于检测外部变化。「管理节点」会提示哪些订阅的本地缓存暂不可读，并保留这些订阅的原勾选和代理提供者定义。两个实现通过同一套 JSON 用例验证整理计划。

没有已保存的勾选名单时，启动和手动刷新都会尝试下载全部订阅，再从实时中转入口组初始化。按中转入口组的 `use` 顺序查询实时节点归属，查不到时按最新下载内容和管理节点展示顺序选择。下载失败时保留原配置和勾选名单。名单为空时取消更新，将下载内容留给「管理节点」重新勾选。已有名单时，刷新只读取状态。

## 影响

需要切换入口时，按配置的指标从最近一轮测速成功的节点中选最快项，缺少结果时按管理节点顺序取首项。新一轮测速开始时清除供整理使用的旧结果，界面继续显示已完成的测速记录和时间。旧版测速记录只有在名称归属无歧义时才用于排序。

每次保存或同步均从当前文件和勾选名单重新整理，使用 `mihomo -t` 校验，备份后写入文件，再请求 Clash 重载。请求未发出或 Clash 明确拒绝时，回退当次写入的文件。重载超时或未收到响应时保留写入的文件，并提示「已写入新配置，Clash 未确认，请刷新状态核对」。

重载成功后，若原入口已不在勾选范围内，自动切换到整理计划选定的入口。切换时核对目标名称是否在实时中转入口组内，并使用保存的节点归属。切换后核对实际入口及固定出口链路，失败时最多重试一次，成功后无需另行提示。

保留订阅和节点的原有顺序，并保留其他策略组还在引用的代理提供者定义。重载时仅把链路盒子管理的代理提供者转换为本地快照，Clash 自己的 HTTP 代理提供者继续按原定义更新。
