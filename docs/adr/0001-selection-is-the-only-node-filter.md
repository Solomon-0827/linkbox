# 0001 勾选名单决定中转节点

## 背景

两个平台曾根据不同的规则保留节点，同名节点也可能让测速使用另一份订阅的配置。

## 决策

移除屏蔽名单，直接丢弃旧屏蔽数据，无需迁移、备份或提示。每个已勾选的名称只有一个节点归属。整理时以勾选名单和最新订阅的交集为准，实时中转入口组用于检测外部变化。「管理节点」会提示哪些订阅的本地缓存暂不可读，并保留这些订阅的原勾选和代理提供者定义。首次初始化和升级时重新下载全部订阅。首次缺少勾选名单时，按订阅和节点的展示顺序，从实时组中为每个名字选定第一个匹配项。任一订阅下载失败时保留原配置和勾选名单，下次启动或手动刷新再试。没有匹配节点时请到「管理节点」勾选。两个实现通过同一套 JSON 用例验证整理计划。

## 影响

需要切换入口时，按配置的指标从最近一轮测速成功的节点中选最快项，缺少结果时按管理节点顺序取首项。新一轮测速开始时清除供整理使用的旧结果，界面继续显示已完成的测速记录和时间。旧版测速记录只有在名称归属无歧义时才用于排序。

校验后先保存待完成的更新记录，再写入计划中的文件并请求重载。首次请求发送前失败，或 Clash 返回带响应体的 HTTP 错误时，回退文件和勾选名单。请求已发送但响应丢失时，保留新文件并在约 10 秒内读取状态确认。若成员名称集合相同但节点归属改变，必须收到成功响应才能确认。重载未确认时暂停保存、同步和入口切换。

启动或手动刷新会补写中断的更新，然后重载并核对实时中转入口成员集合。若文件已写完且实时成员集合已确认，直接检查是否还需要切换。成员集合一致时，每个名称的归属取自勾选名单，由链路盒子写入的代理提供者筛选规则保证唯一。确认后保留仍在勾选名单内的实时入口，否则按最新有效测速结果或勾选顺序切换。切换前后均核对成员集合、目标归属和固定出口链路，失败且仍需切换时再试一次，成功后短暂等待并再次核对。若名单为空，整次更新取消。

日常刷新只读取状态。若在 Clash 中把中转入口改用恰好提供相同成员名称的其他代理提供者，链路盒子无法识别这项变化，可以重新保存选择来应用链路盒子的配置。

保留订阅和节点的原有顺序，并保留其他策略组还在引用的代理提供者定义。重载时仅把链路盒子管理的代理提供者转换为本地快照，Clash 自己的 HTTP 代理提供者继续按原定义更新。
