# 使用与本机配置

## Clash Verge

链路盒子通过本机控制接口连接 Clash Verge。Mac 使用当前用户的 Clash Verge 服务 socket；请启用 Clash Verge 服务模式。Windows 自动发现当前用户的命名管道，也支持已配置的本机 TCP 控制端口。不要为此开放局域网控制端口。

固定组名为 `中转入口` 和 `美国静态家宽`。后者应包含 `dialer-proxy: 中转入口`。GLOBAL 必须选择美国静态家宽，而不是直接选择机场节点。

默认预期出口由固定节点的 `server` IP 推断。服务器地址与实际公网出口不同，或服务器使用域名时，需要在本机设置预期 IP：Mac 的 `settings.json` 使用 `expected_ip`，Windows 使用 `expectedIP`。

## 本机数据目录

- Mac：`~/Library/Application Support/ProxyToolbox`
- Windows：`%APPDATA%/链路盒子`（Electron 用户数据目录）。网络检查不再自动保存报告；检查完成后可点击“下载报告”。

程序不会把本机设置、订阅、测试记录上传到仓库。Net.Coffee 和 ipwho.is 请求会按其正常用途查询所见出口信息。

## 管理订阅节点

点击「管理节点」读取 Clash Verge 本地订阅。左侧列出订阅与已选数量，右侧展示节点名称和协议。可全选或取消本组，也可批量操作全部订阅。同名节点会显示在各自的订阅中，勾选其中一个会取消另一处的勾选。全部选中时优先保留已勾选的归属，其余同名节点按订阅展示顺序选第一项。

点击「保存选择」将勾选名单应用到中转入口组。主列表的批量移除也会更新名单和中转入口组。勾选名单在本机保存，测速与切换使用每个名称所选订阅的节点。

使用链路盒子管理的订阅源的其他策略组也只会看到已勾选的节点，需要全部节点的策略组请使用 Clash Verge 自己的订阅源。
若其他策略组仍引用链路盒子已停用的代理提供者，该组可能会继续使用原筛选规则，直到你手动编辑该策略组。

## 同步订阅

点击「更新全部订阅」下载 Clash Verge 当前管理的订阅，刷新本地缓存和节点列表。已保存的勾选只保留与最新订阅的交集。已删除的订阅和失效节点会从名单消失，新增节点需在管理节点中勾选。对话框内尚未保存的勾选改动会保留到仍存在的节点上。

没有已保存的勾选名单时，链路盒子会在启动和手动刷新时尝试同步 Clash Verge 订阅，再从实时中转入口组中初始化名单。同名节点优先使用当前中转入口组按 `use` 顺序列出的订阅。无法查询归属时，按管理节点的展示顺序选择。已有勾选名单时，刷新只读取状态。

如果看到「已写入新配置，Clash 未确认，请刷新状态核对」，请刷新后查看当前入口，也可以重新保存或同步。

如果当前入口已失效、被取消勾选或在 Clash Verge 选到了名单之外的节点，保存或更新时会自动使用已勾选节点中按动态测速设置的指标最快的一项。没有可用测速结果时，使用按管理节点展示顺序排列的第一项。此操作独立于动态测速的自动换节点开关，不触发新测速。

保存和更新会先校验配置，再热加载，并核对固定出口及中转入口。订阅索引异常、下载失败或所有已勾选节点失效时会取消更新。若没有可保留的节点，请在管理节点中重新勾选。配置备份留在本机 `backups` 目录。

若订阅包含专用 DNS，更新会把相应域名策略带入 Clash 的 `dns.proxy-server-nameserver-policy`，供中转节点解析和测速使用。

## 检查和测速

「网络检查」菜单提供本地检查和 Net.Coffee 入口。检查结果可用「下载报告」保存。

「全链路延迟」右侧的测速图标同时测入口和固定出口的完整链路。当前入口和其他已勾选节点一起测速。测速使用独立临时 Mihomo 内核、物理网卡和本机端口，TUN 关闭。检测到物理网络或当前链路变化会停止，结束时只清理本轮创建的进程。全链路测速以探测返回的公网 IP 核验固定出口。

窗口底部的「动态测速」控制启动和定时测速，旁边的齿轮可设置间隔（1–1440 分钟）、并发数（1–10，默认 5）和自动换节点。手动测速也使用此并发数。动态测速的自动切换默认关闭。开启后只采用本轮结果，候选节点必须通过固定出口验证。当前链路可用时，新节点至少快 20 毫秒且快 10% 才会切换。当前链路验证失败时，可切到本轮验证通过的节点。
